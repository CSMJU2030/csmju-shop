# frontend — หน้าเว็บ CSMJU-Shop

**Next.js 16 (App Router)** + React 19 + Tailwind CSS 4 · ดึงข้อมูลจาก NestJS API **ทุกหน้า ไม่มีข้อมูลจำลอง**

---

## เปิดใช้งาน

ต้องเปิด **สองหน้าต่าง** เพราะ backend กับ frontend รันแยกกัน

**หน้าต่างที่ 1 — backend** (โฟลเดอร์ `csmju-shop`) พอร์ต 5028

```powershell
cd C:\Users\krits\Desktop\csmju-shop
npm run dev
```

**หน้าต่างที่ 2 — frontend** (โฟลเดอร์ `csmju-shop\frontend`) พอร์ต 3228

```powershell
cd C:\Users\krits\Desktop\csmju-shop\frontend
npm install     # ครั้งแรกครั้งเดียว
npm run dev
```

เปิด <http://localhost:3228>

> ใช้พอร์ต 3228 เพราะ 5028 เป็นของ backend
> ถ้าหน้าเว็บขึ้นว่า "ต่อกับเซิร์ฟเวอร์ไม่ได้" แปลว่าลืมเปิด backend ในหน้าต่างที่ 1

**โหมด production**

```powershell
npm run build
npm start
```

## หน้าที่มี

| เส้นทาง | หน้า | API ที่ใช้ |
|---|---|---|
| `/` | สินค้าประจำสาขา — กรองพร้อมส่ง/พรีออเดอร์ เลือกตัวเลือก หยิบลงตะกร้า | `GET /api/products` |
| `/checkout` | ยืนยันคำสั่งซื้อ — เลือกวิธีรับ แนบสลิป สั่งซื้อ | `GET /api/users` · `POST /api/orders` |
| `/orders/[id]` | สถานะคำสั่งซื้อ — แบบรับที่สาขาโชว์ QR จาก `pickup_code` จริง · แบบจัดส่งโชว์ชื่อขนส่ง เลขพัสดุ และปุ่มติดตามพัสดุ | `GET /api/orders/:id` |
| `/staff` | ภาพรวมร้าน — ยอดขาย สลิปค้าง คำสั่งซื้อล่าสุด | `GET /api/orders/stats/summary` |
| `/staff/products` | จัดการสินค้า — เพิ่ม/แก้ไข/ลบ อัปโหลดรูป ตั้งตัวเลือกและสต็อก | `GET POST PUT DELETE /api/products` · `/api/variants` · `POST /api/uploads/image` |
| `/staff/orders` | คำสั่งซื้อทั้งหมด — ยืนยัน/ปฏิเสธการชำระเงิน แจ้งของพร้อม กรอกเลขพัสดุของออร์เดอร์แบบจัดส่ง และลบออร์เดอร์ที่รับของไปแล้ว | `GET /api/orders` · `PATCH /api/orders/:id/payment-status` · `PATCH /api/orders/:id/order-status` · `DELETE /api/orders/:id` |
| `/staff/stock` | สต็อกและพรีออเดอร์ — ยอดที่ต้องผลิต + ยอดขายรายสินค้า + อนุมัติ/ปฏิเสธสลิป | `GET /api/orders` · `GET /api/variants` · `PATCH /api/orders/:id/payment-status` |
| `/staff/pickup` | จุดตรวจรับสินค้า — **สแกน QR ด้วยกล้อง** หรือกรอกรหัสเอง ตรวจสอบ บันทึกส่งมอบ | `POST /api/pickup-logs/verify` · `POST /api/pickup-logs` |

### เลขพัสดุและลิงก์ติดตาม

ออร์เดอร์แบบจัดส่งจะมีปุ่ม **ใส่เลขพัสดุ** ที่ `/staff/orders` — เลือกบริษัทขนส่งจากรายการแล้วกรอกเลขติดตาม
บันทึกแล้วสถานะจะเปลี่ยนเป็น "จัดส่งแล้ว" ให้เอง และลูกค้าเห็นเลขพร้อมปุ่มกดไปเช็คพัสดุทันที

รายชื่อขนส่งและแม่แบบลิงก์เช็คพัสดุอยู่ในไฟล์เดียว: **`lib/carriers.js`**
ถ้าขนส่งเจ้าไหนเปลี่ยน URL หรืออยากเพิ่มเจ้าใหม่ แก้ที่ไฟล์นี้ไฟล์เดียว ไม่ต้องแตะฐานข้อมูล

### สแกน QR ด้วยกล้อง (`/staff/pickup`)

กดปุ่ม **เปิดกล้องสแกน QR** แล้วยกบัตรรับสินค้าของนักศึกษาให้อยู่ในกรอบ
อ่านได้เมื่อไหร่ระบบจะเติมรหัสลงช่องและค้นหาออร์เดอร์ให้ทันที ไม่ต้องกดอะไรอีก
ใช้ **jsQR** ถอดรหัสจากภาพในเครื่อง — ไม่ส่งภาพจากกล้องออกไปไหนทั้งสิ้น
ตัวไลบรารีเก็บไว้ในโปรเจกต์ที่ `lib/vendor/jsqr.js` (Apache-2.0) จึงไม่ต้องติดตั้ง package เพิ่ม

> **เปิดกล้องได้เฉพาะ `http://localhost:3228` หรือเว็บที่เป็น `https://`**
> เป็นกฎของเบราว์เซอร์เอง ถ้าเปิดผ่าน IP เครื่อง (เช่น `http://192.168.1.5:3228`) กล้องจะถูกบล็อก
> หน้าเว็บจะขึ้นคำอธิบายให้ และยังพิมพ์รหัสมือได้ตามปกติ

ครั้งแรกที่กด เบราว์เซอร์จะถามขออนุญาตใช้กล้อง — ต้องกด "อนุญาต"
ถ้าเครื่องมีกล้องหลายตัวจะมีช่องให้เลือกกล้องใต้กรอบภาพ

## ใช้ทดสอบฐานข้อมูลยังไง

หน้าเว็บทั้งหมดยิง API จริง ทุกอย่างที่กดจึงเขียนลง PostgreSQL จริง เดินตามนี้แล้วจะได้เห็นการทำงานครบวงจร

1. **หน้าแรก** กด `+` ที่เสื้อโปโล → สังเกตว่า "คงเหลือ" คือเลขจริงจากตาราง `product_variants`
2. **ตะกร้า → แนบสลิป → ยืนยันคำสั่งซื้อ** → backend ตัดสต็อก คำนวณยอด ออกเลขที่และ `pickup_code` ในคำสั่งเดียว
3. **กลับหน้าแรก** จะเห็นว่าสต็อกลดลงตามจำนวนที่สั่งจริง
4. **บัตรรับสินค้า** ที่เด้งมา — QR สร้างจาก `pickup_code` ในฐานข้อมูล ไม่ใช่รูปตายตัว
5. **`/staff/stock`** → กด **อนุมัติ** ที่สลิปของออร์เดอร์นั้น → `payment_status` เป็น `paid` และ `order_status` เป็น `confirmed` อัตโนมัติ
6. **`/staff/pickup`** → กรอก `pickup_code` → ติ๊กยืนยันตัวตน → **ยืนยันการส่งมอบ** → เกิดแถวใหม่ใน `pickup_logs` และออร์เดอร์เปลี่ยนเป็น `completed`
7. เปิด `npx prisma studio` เทียบดูได้ว่าข้อมูลเปลี่ยนตามจริงทุกขั้น

ลองกรณีที่ต้องพัง: สั่งจำนวนเกินสต็อก จะขึ้นข้อความจาก backend ว่าสต็อกไม่พอ และเลือกจัดส่งโดยไม่กรอกที่อยู่จะถูกปฏิเสธ

รีเซ็ตข้อมูลกลับจุดเริ่มต้นเมื่อไหร่ก็ได้ด้วย `npm run seed` ที่โฟลเดอร์ backend

## หมายเหตุสำหรับคนอ่านโค้ด

**`'use client'`** — หน้าที่มีปุ่ม ฟอร์ม หรือ state ต้องใส่บรรทัดนี้บนสุด ส่วน `layout.jsx` ทั้งสองอันไม่มี state
จึงเป็น server component ตามค่าเริ่มต้น เร็วกว่าเพราะไม่ต้องส่ง JS ของมันไปที่เบราว์เซอร์

**`next.config.mjs` ทำหน้าที่แทน proxy** — เขียน `fetch('/api/products')` ในโค้ดได้ตรง ๆ Next จะส่งต่อไปที่
`localhost:5028/api/products` ให้เอง เบราว์เซอร์เห็นเป็น origin เดียวกันจึงไม่ติด CORS
ถ้า backend ย้ายพอร์ต ให้แก้ `API_TARGET` ในไฟล์ `.env` (ดูตัวอย่างที่ `.env.example`)

**ตะกร้าเริ่มจากค่าว่างเสมอ** แล้วค่อยอ่าน `localStorage` ตอน mount — ทำแบบนี้เพื่อให้ HTML ที่ server สร้าง
ตรงกับรอบแรกของ client ไม่งั้น Next จะเตือน hydration mismatch

**`app/(shop)/`** วงเล็บแปลว่าเป็น route group — ใช้จัดกลุ่มให้ใช้ layout ร่วมกัน **โดยชื่อโฟลเดอร์ไม่โผล่ใน URL**
`app/(shop)/checkout/page.jsx` จึงเป็น `/checkout` ไม่ใช่ `/shop/checkout`

## ข้อจำกัดที่ควรรู้

- **ยังไม่มีระบบล็อกอิน** — หน้าเช็คเอาต์จึงให้เลือกผู้สั่งซื้อจากตาราง `users` ตรง ๆ และหน้าจุดรับสินค้าให้เลือกเจ้าหน้าที่เอง ของจริงต้องมาจาก token หลังล็อกอิน
- **สลิปยังไม่ได้อัปโหลดไฟล์จริง** — schema เก็บ `payment_slip` เป็นข้อความ หน้าเว็บจึงส่งแค่ชื่อไฟล์ไป (ระบบอัปโหลดรูปสินค้าทำไว้แล้วที่ `POST /api/uploads/image` เอามาใช้ซ้ำกับสลิปได้)
- **รูปสินค้าใช้ `<img>` ไม่ใช่ `next/image`** เพราะรูปมาจาก backend ของเราเองผ่าน rewrite · สินค้าที่ไม่มีรูปจะวาด SVG ตามหมวดหมู่ให้แทน
- **ลิงก์เช็คพัสดุเป็นแม่แบบที่เขียนไว้เอง** — ถ้าขนส่งเจ้าไหนเปลี่ยนรูปแบบ URL ต้องแก้ที่ `lib/carriers.js` (ขนส่งที่หน้าเว็บไม่รับเลขทาง URL เช่น J&T และ SCG จะให้ลูกค้ากดคัดลอกเลขไปวางเอง)
- **ทุกหน้าดึงข้อมูลฝั่ง client** เพราะข้อมูลเปลี่ยนตลอด (สต็อก สถานะออร์เดอร์) ถ้าอยากได้ SSR จริง ๆ ต้องให้ server component ยิงไปที่ `http://localhost:5028` ตรง ๆ แทนการใช้ rewrites
- **สแกน QR ด้วยกล้องใช้ได้เฉพาะ `localhost` หรือ `https://`** ตามกฎ secure context ของเบราว์เซอร์ — ยังพิมพ์รหัสเองได้เสมอ
